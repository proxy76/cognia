# Task M2-006: User profile API

**Milestone:** M2 Auth & Profiles
**Dependencies:** M2-003

## Goal
Implement GET /users/me, PUT /users/me, and GET /users/{userId} endpoints. These serve the authenticated user's full profile, allow profile updates, and expose another user's public profile.

## Why This Task Exists
Profile data is displayed throughout the app (profile screen, creator info on videos, leaderboards). A dedicated profile API separates profile concerns from auth and provides the data layer for the profile UI.

## Non-Goals
- No avatar file upload (just storing a URL string)
- No category editing through this API (that is the onboarding/preferences endpoint in M3)
- No follower/friend management (those are M7 Social tasks)

## Acceptance Criteria
- [ ] GET /api/v1/users/me returns full profile: id, email, displayName, avatarUrl, role, level, totalPoints, categories, badgeCount, followerCount, followingCount, friendCount
- [ ] PUT /api/v1/users/me updates displayName and/or avatarUrl and returns updated profile
- [ ] PUT /api/v1/users/me ignores attempts to change role, email, or points
- [ ] GET /api/v1/users/{userId} returns public profile: id, displayName, avatarUrl, role, level, followerCount, videoCount, badges
- [ ] GET /api/v1/users/{userId} returns 404 for unknown userId
- [ ] All profile endpoints require authentication (401 without valid token)
- [ ] Profile DTOs are defined in the shared module

## Tests Required
- Get own profile: authenticated user receives full profile data
- Update profile: change displayName, verify response reflects change
- Update profile with restricted fields: role/email fields are ignored
- Get other user's public profile: returns limited public fields
- Get unknown user: returns 404
- Unauthorized access to any profile endpoint: returns 401
