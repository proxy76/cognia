# Task M1-002: Set up backend skeleton with Ktor

**Milestone:** M1 Foundation
**Dependencies:** None

## Goal
Configure the server module with Ktor plugins including content negotiation (JSON), CORS, status pages, and WebSocket support. The server should start and respond to a health-check endpoint.

## Why This Task Exists
The backend skeleton provides the foundational HTTP server that all API routes, middleware, and services will be installed into. Setting up the plugin pipeline first means subsequent tasks can focus on feature logic without worrying about server bootstrapping.

## Source Docs
- docs/06-api-contracts.md (for understanding the API surface the server will eventually host)
- docs/12-deployment-dev-macbook.md (for port and host configuration)

## Non-Goals
- No route implementations beyond a basic health-check
- No business logic or service classes
- No database connectivity (handled in M1-003)
- No authentication/authorization logic

## Files Expected
- server/build.gradle.kts
- server/src/main/kotlin/com/cognia/app/Application.kt
- server/src/main/kotlin/com/cognia/app/plugins/Serialization.kt
- server/src/main/kotlin/com/cognia/app/plugins/CORS.kt
- server/src/main/kotlin/com/cognia/app/plugins/StatusPages.kt
- server/src/main/kotlin/com/cognia/app/plugins/WebSockets.kt
- server/src/main/kotlin/com/cognia/app/plugins/Routing.kt

## Acceptance Criteria
- [ ] Server starts on configurable host/port without errors
- [ ] Content negotiation is configured for JSON via kotlinx.serialization
- [ ] CORS is configured to allow requests from localhost development origins
- [ ] Status pages plugin returns structured JSON error responses
- [ ] WebSocket support is installed (no WebSocket routes needed yet)
- [ ] A GET /health endpoint returns 200 OK
- [ ] Gradle builds the server module without errors

## Tests Required
- Application starts without error test (embedded server test)
- Health-check endpoint returns 200 OK
