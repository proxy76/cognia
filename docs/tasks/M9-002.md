# Task M9-002: Notification REST API

**Milestone:** M9 Notifications & Analytics
**Dependencies:** M9-001

## Goal
Expose REST endpoints: GET /notifications (paginated), PUT /notifications/{id}/read, and PUT /notifications/read-all for managing notification state.

## Why This Task Exists
Users need to retrieve their notifications and manage read state through a standard REST API. This provides the baseline notification access before realtime delivery is added.

## Source Docs
- M9-001 (Notification creation and storage)
- API design conventions

## Non-Goals
- No realtime push (that is M9-003)

## Files Expected
- `server/src/main/kotlin/.../notification/NotificationController.kt`
- `server/src/main/kotlin/.../notification/NotificationDtos.kt`

## Acceptance Criteria
- [ ] GET /notifications returns paginated notifications for the authenticated user
- [ ] PUT /notifications/{id}/read marks a single notification as read
- [ ] PUT /notifications/read-all marks all notifications as read
- [ ] Unread count is available (either as header or in response)
- [ ] Authentication required on all endpoints

## Tests Required
- List notifications with pagination
- Mark single notification as read
- Mark all notifications as read
- Unread count is accurate
- User can only see their own notifications
