# Task M3-001: Category CRUD and Seed Data

**Milestone:** M3 Onboarding
**Dependencies:** M1-003

## Goal
Create the Category table, repository, CRUD API endpoints, and seed the database with initial categories.

## Why This Task Exists
Categories are the foundation for onboarding recommendations and content organization. Users need to select categories during onboarding, and creators tag content with categories. The seed data ensures a baseline set of categories is always available.

## Source Docs
- Domain model documentation for Category entity
- Database schema design

## Non-Goals
- No AI recommendation logic — that belongs in M3-002
- No user-category preference linking (that's M3-003)

## Files Expected
- Category entity/table definition
- Category repository interface and implementation
- Category CRUD API controller and routes
- Database migration for categories table
- Seed data script or migration with initial categories

## Acceptance Criteria
- [ ] Category table created with appropriate fields (id, name, description, icon, etc.)
- [ ] Repository supports create, read (single and list), update, delete
- [ ] REST API exposes GET /categories, GET /categories/{id}, POST /categories, PUT /categories/{id}, DELETE /categories/{id}
- [ ] Seed data populates initial categories on first run
- [ ] Duplicate category names are rejected

## Tests Required
- CRUD operations: create, read, update, delete category
- List all categories returns seeded data
- Seed data is present after initialization
- Duplicate name rejection
- Not-found handling for invalid category ID
