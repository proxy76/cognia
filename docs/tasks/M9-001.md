# Task M9-001: Notification creation and storage

**Milestone:** M9 Notifications & Analytics
**Dependencies:** M1-003

## Goal
Create the Notification table, repository, and NotificationService that creates notifications for key events: friend request received, content approved, content rejected, badge earned, and other significant actions.

## Why This Task Exists
Notifications keep users informed about activity relevant to them. The creation and storage layer is the foundation that the delivery mechanisms (REST API, WebSocket) build upon.

## Source Docs
- M1-003 (Database setup)
- Notification specs

## Non-Goals
- No delivery mechanism (REST or WebSocket) — those are M9-002 and M9-003

## Files Expected
- `server/src/main/kotlin/.../notification/Notification.kt`
- `server/src/main/kotlin/.../notification/NotificationRepository.kt`
- `server/src/main/kotlin/.../notification/NotificationService.kt`
- Database migration for notifications table

## Acceptance Criteria
- [ ] Notification table stores type, recipient, message, read status, timestamp, and optional reference data
- [ ] NotificationService creates notifications for each supported event type
- [ ] Notifications are stored and retrievable per user
- [ ] Read/unread status is tracked

## Tests Required
- Notification created for friend request event
- Notification created for content approved event
- Notification created for badge earned event
- Each notification type stored correctly with appropriate data
- Notifications retrievable per user
