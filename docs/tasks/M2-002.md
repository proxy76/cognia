# Task M2-002: Registration and login API (email/password)

**Milestone:** M2 Auth & Profiles
**Dependencies:** M1-003, M2-001

## Goal
Implement POST /auth/register and POST /auth/login endpoints. Registration creates a new user in the database with a bcrypt-hashed password. Login validates credentials against stored hashes. Both endpoints return an AuthResponse on success.

## Why This Task Exists
Email/password authentication is the primary auth mechanism and the foundation that OAuth and token management build upon. Users need to be able to create accounts and sign in before any other feature is usable.

## Acceptance Criteria
- [ ] POST /api/v1/auth/register accepts RegisterRequest body
- [ ] Registration creates a new User row with bcrypt-hashed password
- [ ] Registration returns 201 with AuthResponse (userId, token, refreshToken)
- [ ] Registration returns 409 if email already exists
- [ ] POST /api/v1/auth/login accepts LoginRequest body
- [ ] Login returns 200 with AuthResponse on valid credentials
- [ ] Login returns 401 on wrong password or unknown email
- [ ] Passwords are never stored or logged in plain text
- [ ] Input validation: reject empty email, empty password, malformed email
- [ ] UserRepository provides insert and findByEmail operations

## Tests Required
- Register success: new email returns 201 with valid AuthResponse
- Register duplicate email: returns 409 with error message
- Login success: valid credentials return 200 with AuthResponse
- Login wrong password: returns 401
- Login unknown email: returns 401
- Register with missing fields: returns 400
