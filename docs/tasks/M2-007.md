# Task M2-007: Registration and login UI screens

**Milestone:** M2 Auth & Profiles
**Dependencies:** M1-006, M2-002

## Goal
Build Compose Multiplatform UI for the Welcome screen (sign up / log in choice), Registration screen (email, password, display name form), and Login screen (email, password form) with client-side form validation and navigation between screens.

## Why This Task Exists
Users need a visual interface to create accounts and sign in. These screens are the entry point to the entire app and must handle input validation, loading states, and error display gracefully to provide a solid first impression.

## Source Docs
- docs/08-ui-flows.md (Authentication Flow section)
- docs/06-api-contracts.md (POST /auth/register, POST /auth/login)
- docs/09-coding-standards.md

## Non-Goals
- No onboarding flow after registration (covered in M3)
- No OAuth UI buttons (Google/Apple sign-in buttons come in a follow-up)
- No password reset or forgot password flow

## Files Expected
- composeApp/src/commonMain/kotlin/com/cognia/app/ui/auth/WelcomeScreen.kt
- composeApp/src/commonMain/kotlin/com/cognia/app/ui/auth/RegisterScreen.kt
- composeApp/src/commonMain/kotlin/com/cognia/app/ui/auth/LoginScreen.kt
- composeApp/src/commonMain/kotlin/com/cognia/app/ui/auth/AuthViewModel.kt

## Acceptance Criteria
- [ ] Welcome screen displays Sign Up and Log In options
- [ ] Registration screen has email, password, and display name input fields
- [ ] Login screen has email and password input fields
- [ ] Client-side validation: email format check, password minimum length, non-empty display name
- [ ] Validation errors shown inline next to the relevant field
- [ ] Submit button triggers API call via AuthViewModel
- [ ] Loading state shown while API call is in progress (button disabled, spinner or indicator)
- [ ] Success navigates to the appropriate destination (onboarding for register, home for login)
- [ ] API error messages displayed to the user (e.g. "Email already in use", "Invalid credentials")
- [ ] Navigation between Welcome, Register, and Login screens works correctly

## Tests Required
- AuthViewModel: initial state is idle with empty fields
- AuthViewModel: register success updates state to success with auth data
- AuthViewModel: register failure updates state with error message
- AuthViewModel: login success updates state to success
- AuthViewModel: login failure updates state with error message
- AuthViewModel: loading state is set while request is in-flight
