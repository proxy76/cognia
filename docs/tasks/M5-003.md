# Task M5-003: Quiz Attempt and Scoring Logic

**Milestone:** M5 Quiz & Progression
**Dependencies:** M5-001

## Goal
Implement POST /quizzes/{id}/attempt that validates submitted answers against correct answers, computes a score, awards base points, and stores the attempt record.

## Why This Task Exists
The core learning loop requires users to take quizzes and receive immediate feedback. Scoring and attempt storage enable progress tracking, and base points feed into the gamification system.

## Source Docs
- Quiz domain models from M5-001
- Scoring rules documentation
- Attempt/progress tracking design

## Non-Goals
- No difficulty multiplier for points — that belongs in M5-004
- No levels or badges
- No leaderboard

## Files Expected
- Quiz attempt entity/table definition
- Quiz attempt repository
- Scoring service interface and implementation
- Attempt controller/route
- Attempt request/response DTOs
- Database migration for attempts table

## Acceptance Criteria
- [ ] POST /quizzes/{id}/attempt accepts a list of answer selections
- [ ] Answers validated against correct options
- [ ] Score computed as number of correct answers / total questions
- [ ] Base points awarded (e.g., 10 points per correct answer)
- [ ] Attempt record stored with user ID, quiz ID, answers, score, points, timestamp
- [ ] Response includes score, points earned, and per-question correctness
- [ ] User can retake quizzes (multiple attempts allowed)

## Tests Required
- All correct answers yield full score and max base points
- Partial correct answers yield proportional score and points
- All wrong answers yield zero score and zero points
- Attempt record is stored in database
- Multiple attempts by same user are allowed and stored
- Invalid quiz ID returns 404
- Missing answers handled gracefully
