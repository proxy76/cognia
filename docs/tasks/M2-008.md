# Task M2-008: Profile screen UI

**Milestone:** M2 Auth & Profiles
**Dependencies:** M2-006, M2-007

## Goal
Build a Compose Multiplatform profile screen that displays the current user's info (display name, avatar, role), level and points, a badges placeholder section, and basic stats (follower/following/friend counts).

## Why This Task Exists
The profile screen gives users a sense of identity and progress within the app. Showing level, points, and badges motivates continued engagement. This screen is also the entry point for future settings and content management features.

## Source Docs
- docs/08-ui-flows.md
- docs/06-api-contracts.md (GET /users/me response shape)
- docs/04-domain-model.md (User, UserProfile)
- docs/09-coding-standards.md

## Non-Goals
- No list of user's created content (videos, quizzes)
- No settings editing (display name, avatar changes)
- No badge detail views or badge earning logic
- No follower/friend list navigation

## Files Expected
- composeApp/src/commonMain/kotlin/com/cognia/app/ui/profile/ProfileScreen.kt
- composeApp/src/commonMain/kotlin/com/cognia/app/ui/profile/ProfileViewModel.kt

## Acceptance Criteria
- [ ] Profile screen fetches data from GET /users/me via ProfileViewModel
- [ ] Displays user's display name and avatar (or placeholder if no avatar)
- [ ] Displays user's role as a label or badge
- [ ] Displays current level and total points
- [ ] Shows a badges section with count (placeholder UI for individual badges)
- [ ] Shows stats row: follower count, following count, friend count
- [ ] Loading state shown while profile data is being fetched
- [ ] Error state shown if the API call fails, with a retry option
- [ ] Screen is accessible from the app's main navigation

## Tests Required
- ProfileViewModel: loading state is set when fetch begins
- ProfileViewModel: success state contains profile data from API
- ProfileViewModel: error state is set when API call fails
- ProfileViewModel: retry triggers a new fetch
