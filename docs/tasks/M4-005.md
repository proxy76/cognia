# Task M4-005: Video Serving Endpoint

**Milestone:** M4 Content & Playback
**Dependencies:** M4-003

## Goal
Implement a GET endpoint that serves processed video files with HTTP range request support for streaming playback.

## Why This Task Exists
The mobile app needs to stream video content efficiently. HTTP range requests allow seeking within videos and progressive loading without downloading the entire file first.

## Source Docs
- Video entity from M4-001
- Processing pipeline from M4-003
- HTTP range request specification (RFC 7233)

## Non-Goals
- No CDN integration
- No adaptive bitrate streaming (HLS/DASH)
- No caching layer

## Files Expected
- Video serving controller/route
- Range request handling logic
- Content-Type and Content-Range header management
- File streaming utility

## Acceptance Criteria
- [ ] GET /videos/{id}/stream serves the processed video file
- [ ] Supports HTTP Range headers for partial content (206 responses)
- [ ] Returns correct Content-Type, Content-Length, and Content-Range headers
- [ ] Returns 404 for missing or unprocessed videos
- [ ] Only serves PUBLISHED videos (or owner's own videos)
- [ ] Handles concurrent requests efficiently

## Tests Required
- Full video file served successfully
- Range request returns partial content with correct headers
- Multiple range requests cover entire file
- 404 returned for non-existent video
- 404 returned for unprocessed video
- Access control: unpublished video not served to non-owner
