# Task M2-003: JWT token issuance and validation

**Milestone:** M2 Auth & Profiles
**Dependencies:** M2-002

## Goal
Implement JWT creation on login/register, token validation middleware for protected endpoints, and refresh token storage with rotation. Wire JWT issuance into the auth endpoints from M2-002.

## Why This Task Exists
Stateless authentication via JWT is essential for securing all API endpoints. The refresh token mechanism allows long-lived sessions without exposing long-lived access tokens. This task provides the security infrastructure that every subsequent authenticated endpoint depends on.

## Acceptance Criteria
- [ ] JWT access tokens are generated with userId, email, and role claims
- [ ] Access tokens have a configurable expiration (e.g. 15 minutes)
- [ ] Refresh tokens are stored in the database and associated with a user
- [ ] POST /api/v1/auth/refresh accepts RefreshRequest and returns new token pair
- [ ] Refresh token rotation: old refresh token is invalidated when a new one is issued
- [ ] Auth middleware extracts and validates JWT from Authorization: Bearer header
- [ ] Middleware rejects expired tokens with 401
- [ ] Middleware rejects malformed or missing tokens with 401
- [ ] Auth endpoints (register, login) now return real JWT tokens instead of placeholders
- [ ] JWT secret is loaded from environment configuration (M1-008)

## Tests Required
- Token generation: verify generated JWT contains correct claims (userId, email, role)
- Token validation: valid token passes middleware, request proceeds
- Expired token: middleware returns 401
- Malformed token: middleware returns 401
- Missing Authorization header: middleware returns 401
- Refresh flow: valid refresh token returns new token pair and invalidates old refresh token
- Refresh with invalid/expired refresh token: returns 401
