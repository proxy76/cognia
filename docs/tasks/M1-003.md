# Task M1-003: Set up SQLite database layer with schema migration

**Milestone:** M1 Foundation
**Dependencies:** M1-002

## Goal
Set up the SQLite database connection, create all tables on startup matching docs/07-database-schema.md, and enable foreign key enforcement via PRAGMA foreign_keys = ON.

## Why This Task Exists
The database schema is the persistence backbone for every feature. Establishing it early, with foreign key enforcement enabled, ensures data integrity constraints are in place before any repository or service code is written.

## Source Docs
- docs/07-database-schema.md

## Non-Goals
- No repository implementations (CRUD operations come in later tasks)
- No seed data or fixtures
- No migration versioning system (schema is created fresh for M1)

## Files Expected
- server/src/main/kotlin/com/cognia/app/database/DatabaseFactory.kt
- server/src/main/kotlin/com/cognia/app/database/tables/*.kt (one file per table or grouped logically)

## Acceptance Criteria
- [ ] SQLite database file is created at a configurable path
- [ ] All tables from docs/07-database-schema.md are created on startup
- [ ] PRAGMA foreign_keys = ON is set on every connection
- [ ] Table creation is idempotent (CREATE TABLE IF NOT EXISTS or equivalent)
- [ ] Column types, nullability, and constraints match the schema doc
- [ ] Foreign key relationships are correctly defined

## Tests Required
- Schema creation test: database initializes and all expected tables exist
- Foreign key enforcement test: inserting a row with an invalid foreign key reference fails
