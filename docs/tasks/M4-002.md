# Task M4-002: Video Upload API (Multipart)

**Milestone:** M4 Content & Playback
**Dependencies:** M4-001, M2-005

## Goal
Implement POST /videos multipart upload endpoint that saves the raw video file to disk and creates a video record with DRAFT status.

## Why This Task Exists
Creators need to upload video content to the platform. This task handles the initial ingestion step — accepting the file and storing it — before any processing occurs.

## Source Docs
- Video entity from M4-001
- Authentication/authorization from M2-005
- File storage design

## Non-Goals
- No video processing or transcoding (that's M4-003)
- No metadata update after creation (that's M4-004)
- No file size validation beyond basic limits

## Files Expected
- Video upload controller/route
- Multipart file handling logic
- File storage service (save to disk)
- Upload request/response DTOs

## Acceptance Criteria
- [ ] POST /videos accepts multipart file upload
- [ ] Raw video file saved to configured storage directory
- [ ] Video record created in database with DRAFT status
- [ ] Response includes video ID and status
- [ ] File size limit enforced
- [ ] Only authenticated creators can upload
- [ ] Accepted video formats validated (mp4, mov, etc.)

## Tests Required
- Successful upload saves file and creates record
- File is persisted to disk at expected path
- Video record created with DRAFT status
- Unauthorized upload request is rejected
- Non-creator role upload is rejected
- Oversized file is rejected
- Invalid file format is rejected
