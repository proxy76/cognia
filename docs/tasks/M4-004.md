# Task M4-004: Video Metadata Update and Status Transition APIs

**Milestone:** M4 Content & Playback
**Dependencies:** M4-001, M2-005

## Goal
Implement PUT /videos/{id} for metadata updates, POST /videos/{id}/submit for regular creators to submit for review, and POST /videos/{id}/publish for licensed creators to publish directly.

## Why This Task Exists
Creators need to update video metadata (title, description, category) after upload and trigger status transitions to move content through the publishing lifecycle. Licensed creators have a faster path to publication.

## Source Docs
- Video entity and state machine from M4-001
- Authentication/authorization from M2-005
- Creator role definitions

## Non-Goals
- No moderation review workflow — that belongs in M8
- No video upload or processing
- No content feed integration

## Files Expected
- Video metadata update controller/route
- Video submit controller/route
- Video publish controller/route
- Request/response DTOs
- Role-based authorization checks

## Acceptance Criteria
- [ ] PUT /videos/{id} updates title, description, category, and difficulty (for licensed creators)
- [ ] Only the video owner can update metadata
- [ ] POST /videos/{id}/submit transitions video from DRAFT to PENDING_REVIEW
- [ ] POST /videos/{id}/publish transitions video from DRAFT to PUBLISHED (licensed creators only)
- [ ] Regular creators cannot use the publish endpoint
- [ ] Invalid state transitions return appropriate errors
- [ ] Authentication required for all endpoints

## Tests Required
- Metadata update succeeds for video owner
- Metadata update rejected for non-owner
- Submit transitions status to PENDING_REVIEW
- Publish transitions status to PUBLISHED for licensed creator
- Publish rejected for regular creator
- Invalid state transition returns error
- Role-based access checks enforced
