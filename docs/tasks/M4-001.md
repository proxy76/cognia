# Task M4-001: Video Entity and Content Status State Machine

**Milestone:** M4 Content & Playback
**Dependencies:** M1-001, M1-003

## Goal
Create the Video table, repository, and a content status state machine with valid transitions enforced at the domain level.

## Why This Task Exists
Videos are the core content type in the platform. The status state machine (e.g., DRAFT -> PENDING_REVIEW -> PUBLISHED) ensures content follows a controlled lifecycle, preventing invalid transitions and maintaining data integrity.

## Source Docs
- Domain model documentation for Video entity
- Content lifecycle/status flow design
- Database schema design

## Non-Goals
- No video upload functionality
- No video processing or transcoding
- No video serving or streaming

## Files Expected
- Video entity/table definition with status field
- Content status enum with all valid states
- State machine logic enforcing valid transitions
- Video repository interface and implementation
- Database migration for videos table

## Acceptance Criteria
- [ ] Video table created with fields: id, title, description, category, status, creator ID, file URLs, timestamps, etc.
- [ ] Content status enum defines all states (DRAFT, PENDING_REVIEW, PUBLISHED, REJECTED, ARCHIVED, etc.)
- [ ] State machine enforces only valid transitions (e.g., DRAFT -> PENDING_REVIEW, not DRAFT -> PUBLISHED for regular creators)
- [ ] Invalid transitions throw appropriate errors
- [ ] Repository supports CRUD operations
- [ ] Status transitions are logged or auditable

## Tests Required
- All valid state transitions succeed
- All invalid state transitions fail with appropriate error
- CRUD operations: create, read, update, delete video records
- Video creation defaults to DRAFT status
- State machine covers edge cases (e.g., re-submit after rejection)
