# Task M1-008: Set up environment configuration

**Milestone:** M1 Foundation
**Dependencies:** M1-002

## Goal
Create a configuration loading system that reads from environment variables, matching the deployment requirements in docs/12-deployment-dev-macbook.md, with sensible defaults for local development.

## Why This Task Exists
Externalizing configuration from code is essential for running the app in different environments (dev laptop, CI, staging). Having a typed config object with defaults means developers can start the server immediately without any setup, while still being able to override values when needed.

## Source Docs
- docs/12-deployment-dev-macbook.md

## Non-Goals
- No production configuration profiles
- No Docker or container configuration
- No secrets management or vault integration

## Files Expected
- server/src/main/kotlin/com/cognia/app/config/AppConfig.kt
- server/src/main/kotlin/com/cognia/app/config/DatabaseConfig.kt
- server/src/main/kotlin/com/cognia/app/config/ServerConfig.kt
- server/src/main/kotlin/com/cognia/app/config/AuthConfig.kt
- .env.example

## Acceptance Criteria
- [ ] Config values are loaded from environment variables
- [ ] Sensible defaults are provided for all config values (server starts with zero env vars set)
- [ ] Config covers at minimum: server host/port, database path, JWT secret/expiry, CORS origins
- [ ] .env.example documents all available environment variables with example values
- [ ] Config classes are immutable data classes
- [ ] Config is accessible via Koin DI (or a simple singleton if M1-004 is not yet complete)

## Tests Required
- Config loading test with defaults: no env vars set, all config values have expected defaults
- Config loading test with overrides: set env vars, verify config reflects the overridden values
