# Task M1-004: Set up dependency injection (Koin)

**Milestone:** M1 Foundation
**Dependencies:** M1-002

## Goal
Configure Koin dependency injection modules for the backend, creating empty module stubs for each feature area so that subsequent tasks can register their implementations without restructuring.

## Why This Task Exists
A DI framework wired into the application from the start avoids the pain of retrofitting dependency injection later. Empty module stubs also serve as a roadmap of the feature areas that will be built out in subsequent milestones.

## Source Docs
- docs/03-architecture.md (for understanding module boundaries)

## Non-Goals
- No actual service, repository, or controller implementations
- No client-side DI setup (only backend)

## Files Expected
- server/src/main/kotlin/com/cognia/app/di/AppModule.kt (root module that aggregates feature modules)
- server/src/main/kotlin/com/cognia/app/di/DatabaseModule.kt
- server/src/main/kotlin/com/cognia/app/di/AuthModule.kt
- server/src/main/kotlin/com/cognia/app/di/UserModule.kt
- server/src/main/kotlin/com/cognia/app/di/ContentModule.kt
- server/src/main/kotlin/com/cognia/app/di/ChatModule.kt
- server/src/main/kotlin/com/cognia/app/di/ModerationModule.kt
- Additional feature module stubs as needed

## Acceptance Criteria
- [ ] Koin is installed as a Ktor plugin in the application
- [ ] A root module aggregates all feature sub-modules
- [ ] Each feature area has a dedicated Koin module file (even if empty)
- [ ] Application starts successfully with Koin configured
- [ ] Modules follow a consistent naming convention

## Tests Required
- Koin module verification test: `checkModules()` passes with no missing definitions
