# Task M1-005: Set up shared networking (Ktor Client)

**Milestone:** M1 Foundation
**Dependencies:** M1-001

## Goal
Configure a shared Ktor HTTP client in the shared module with JSON serialization, configurable base URL, and an auth token interceptor stub that can be wired up once authentication is implemented.

## Why This Task Exists
The mobile/desktop client needs a centralized, platform-aware HTTP client to communicate with the backend. Setting this up in the shared module allows all platform targets to reuse the same networking logic while plugging in platform-specific engines (OkHttp for Android, Darwin for iOS, etc.).

- docs/03-architecture.md

## Non-Goals
- No actual API call implementations
- No concrete authentication logic (just the interceptor hook)
- No offline caching or retry policies

- shared/src/androidMain/kotlin/com/cognia/app/network/HttpEngineFactory.kt (Android engine)
- shared/src/iosMain/kotlin/com/cognia/app/network/HttpEngineFactory.kt (iOS/Darwin engine)
- shared/src/desktopMain/kotlin/com/cognia/app/network/HttpEngineFactory.kt (Desktop engine, if applicable)

## Acceptance Criteria
- [ ] Shared Ktor HttpClient is created via a factory with JSON content negotiation
- [ ] Base URL is configurable via ApiConfig
- [ ] Auth token interceptor stub is installed (adds Authorization header when token is available)
- [ ] Platform-specific engine implementations are provided for each target
- [ ] Client compiles across all KMP targets
