# Task M2-005: Role-based authorization middleware

**Milestone:** M2 Auth & Profiles
**Dependencies:** M2-003

## Goal
Create middleware that checks the authenticated user's role against a set of required roles for a given endpoint. Provide a utility for route definitions to declare which roles are permitted. Return 403 Forbidden when a user lacks the required role.

## Why This Task Exists
Different features in Cognia are gated by user role (LEARNER, CREATOR, LICENSED_CREATOR, MODERATOR, ADMIN). A reusable authorization layer prevents ad-hoc role checks scattered across routes and ensures consistent enforcement of access policies.

## Non-Goals
- No specific endpoint protections yet (those are applied when each feature's routes are created)
- No permission system beyond role checking
- No UI changes

## Files Expected
- server/src/main/kotlin/com/cognia/app/auth/RoleAuthorization.kt
- server/src/main/kotlin/com/cognia/app/auth/AuthMiddleware.kt (extend with role checking)

## Acceptance Criteria
- [ ] Middleware reads the user's role from the JWT claims set by M2-003
- [ ] Route definitions can declare required roles (e.g. `authorize(UserRole.CREATOR, UserRole.ADMIN) { ... }`)
- [ ] Request with a valid token but insufficient role returns 403 Forbidden
- [ ] Request with no token still returns 401 Unauthorized (auth middleware runs first)
- [ ] ADMIN role has access to all role-gated endpoints
- [ ] Multiple allowed roles can be specified per route
- [ ] Middleware is composable with the existing auth middleware from M2-003

## Tests Required
- LEARNER accessing a CREATOR-only endpoint: returns 403
- CREATOR accessing a CREATOR-allowed endpoint: returns 200
- MODERATOR accessing a MODERATOR-allowed endpoint: returns 200
- ADMIN accessing any role-gated endpoint: returns 200
- Unauthenticated request to a role-gated endpoint: returns 401
- Endpoint with multiple allowed roles: each allowed role returns 200, disallowed role returns 403
