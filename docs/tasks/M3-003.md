# Task M3-003: Preference Persistence API

**Milestone:** M3 Onboarding
**Dependencies:** M3-001, M2-003

## Goal
Implement PUT /onboarding/preferences to save a user's selected categories and self-description. Support retrieving and updating these preferences.

## Why This Task Exists
After the onboarding recommendation step, users confirm their category selections. These preferences must be persisted so the app can personalize the content feed and track user interests over time.

## Source Docs
- Onboarding flow design
- User entity from M2-003
- Category entity from M3-001

## Non-Goals
- No recommendation logic — this task only persists the user's final selections
- No feed personalization logic
- No profile settings UI for editing preferences

## Files Expected
- User preference entity/table (or join table for user-category)
- Preference repository interface and implementation
- Preference API controller and routes
- Database migration for preference storage

## Acceptance Criteria
- [ ] PUT /onboarding/preferences saves category selections and self-description for the authenticated user
- [ ] GET /onboarding/preferences retrieves the current user's saved preferences
- [ ] Updating preferences replaces previous selections
- [ ] Self-description text is stored alongside category selections
- [ ] Invalid category IDs are rejected
- [ ] Requires authentication

## Tests Required
- Save preferences with valid categories
- Retrieve saved preferences
- Update preferences replaces old selections
- Reject invalid category IDs
- Unauthenticated request is rejected
- Empty category list is accepted (user can skip)
